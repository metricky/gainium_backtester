# 006 — a grid force close on a flat position makes every reported figure NaN

## Solution

Fix the root cause named in spec §3: gate the futures `stopAndSell` close's
P&L arithmetic on the position actually existing, using the same condition the
ledger write below it already applies.

## Build order

1. In `closeBot()`'s futures branch, hoist the ledger guard into a local
   `hasPosition = current.qty > 0 && current.entryPrice > 0`, computed before
   `diff`.
2. `diff` and `profit` become `0` when `!hasPosition`; the expressions are
   otherwise unchanged, so an open position takes exactly the path it takes
   today. `profitUsd` follows from `profit` and needs no guard of its own.
3. The existing `if (current.qty > 0 && current.entryPrice > 0)` ledger guard
   becomes `if (hasPosition)` — same condition, named once.

No other call site, no signature change, no new field.

## Contract decisions the spec left open

- **A flat close books no row.** Unchanged from spec 002 §4.2 — there is no
  order to record, and `numerical.all/buy/sell` must not count one.
- **`totalProfit` accrual** still runs unconditionally; it just adds `0`. This
  keeps `positionStats.count` and the `currentBalances = initialBalances +
  totalProfit` line on one path for both cases, rather than forking the branch.
- **`currentBalances` on an empty run** therefore comes out as the untouched
  budget (`initialBalances + 0`), not `0`. That is the figure the equity curve
  and `initialBalancesByAsset` already report, so the result becomes
  self-consistent rather than gaining a new convention.
- **Rounding is untouched.** `returnResult` keeps rounding as it does; the
  point is that it no longer receives a NaN.

## Blast radius

1. **Other call sites.** `closeBot` is called only from `checkPosition` and
   `processBar` in the same file. Nothing else reads `diff`/`profit` from this
   branch.
2. **`core/` submodule.** None in this repo.
3. **CLAUDE.md contracts.** Danger List #13 — this engine runs server-side
   (main-app `:7515` backtest worker) *and* client-side in both dashboards from
   the same published package, so both sides move together. No input or result
   **type** changes. Result values move only on runs that previously reported
   NaN-as-`0`: those now report the figures they earned. A run whose force
   close had an open position is byte-identical, which is the whole of the
   existing test corpus for spec 002 and spec 003.
4. **Other tests.** All of `test/` must stay green — in particular
   `grid-force-close-transaction.spec.ts` (the open-position close) and
   `grid-tpsl-priceReached.spec.ts` (which stop fires).
